Landmaark Project DB Design

Database Table Relationships & Cardinality Flowchart

Explicit mapping of One-to-Many (1:N), Many-to-Many (M:N), One-to-One (1:1), and Recursive Hierarchy relationships.

1 : N One-to-Many
Parent table record connects to multiple child records (e.g. Townships ➔ Properties).
M : N Many-to-Many
Linked via junction table (e.g. Properties ➔ Property_Amenities ➔ Amenities).
1 : 1 One-to-One
Direct single extension record (e.g. Sales ➔ Sales_Audits document verification).
1 : N Self Recursive Upline
Self-referencing foreign key (Users ➔ Sponsor_ID Upline tree).

Parent / Source Table Child / Target Table Type / Symbol Foreign Key (FK) Field Business Logic & Relationship Description
townships properties 1 : N properties.township_id One township contains multiple plots/properties across blocks.
properties amenities M : N property_amenities (Junction) A property has many amenities, and an amenity applies to many properties.
townships places 1 : N places.township_id A township maps to multiple nearby places (highways, schools, hospitals).
categories blogs 1 : N blogs.category_id A blog category (e.g. Real Estate News) groups multiple blog posts.
properties contact_submissions 1 : N contact_submissions.property_id Potential buyers submit lead inquiries for specific properties.
users (Sponsor) users (Downlines) 1 : N Self users.sponsor_id An associate has 1 sponsor, but can build a team of multiple downlines.
properties sales 1 : N sales.property_id A property tracks booking and registry sales transactions.
users sales 1 : N sales.seller_associate_id An associate originates multiple property sales.
sales sales_audits 1 : 1 sales_audits.sale_id Each sale has exactly one audit record verifying agreement & registry PDFs.
sales earnings 1 : N earnings.sale_id One approved sale generates multi-level commission lines up the MLM tree.
pool_runs pool_distributions 1 : N pool_distributions.run_id One global pool distribution batch distributes funds to all qualified associates.
