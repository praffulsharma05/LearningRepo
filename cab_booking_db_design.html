Uber & Rapido System Architecture

Cab & Ride Booking Database Design

Comprehensive ER Model & Realtime Data Pipeline for Riders, Drivers, GPS Tracking, Pricing Surge, OTP Trips, Payments & Reviews.

1 : N One-to-Many
Riders ➔ Rides, Drivers ➔ Rides, Vehicle Types ➔ Vehicles.
M : N Many-to-Many
Riders ➔ Rider_Coupons ➔ Promo Coupons redemption.
1 : 1 One-to-One
Rides ➔ Payments (Each trip generates 1 transaction ledger).
Geospatial 1:N Live Tracking
Rides ➔ Ride_Locations (High-frequency GPS ping log).

    RATINGS_REVIEWS {
        int review_id PK
        int ride_id FK

    }

    DRIVER_DOCUMENTS {
        int document_id PK
        int driver_id FK
        string document_type
        string document_url
        string verification_status
        date expiry_date
    }

    COUPONS_PROMOS {
        int coupon_id PK
        string code
        string discount_type
        decimal discount_value
        decimal min_ride_amount
        date valid_until
    }

    RIDER_COUPONS {
        int rider_id PK_FK
        int coupon_id PK_FK

    }

    SURGE_ZONES {
        int zone_id PK
        string zone_name
        decimal center_latitude
        decimal center_longitude

    }

    SUPPORT_TICKETS {
        int ticket_id PK
        int ride_id FK

Parent / Source Table Child / Target Table Cardinality Type Foreign Key (FK) Field Business Logic & System Flow
riders rides 1 : N rides.rider_id A rider places multiple cab/bike trip requests over time.
drivers rides 1 : N rides.driver_id A driver accepts, picks up, and completes multiple rides.
drivers vehicles 1 : N vehicles.driver_id A driver can register multiple vehicles (Bike, Auto, Sedan), 1 active.
vehicle_types vehicles 1 : N vehicles.vehicle_type_id Category (e.g. Rapido Bike, Uber Go, UberXL) groups vehicles.
drivers driver_documents 1 : N driver_documents.driver_id Driver uploads KYC docs (Driving License, RC, Insurance, Police Verification).
surge_zones rides 1 : N rides.zone_id High demand geographic zones apply 1.2x - 2.5x fare multipliers.
rides payments 1 : 1 payments.sale_id / ride_id Each completed ride generates exactly 1 payment transaction ledger.
rides ride_locations Geospatial 1:N ride_locations.ride_id Realtime GPS tracking pings logged every 5 seconds during active trip.
rides ratings_reviews 1 : N ratings_reviews.ride_id Two-way review system: Rider rates Driver & Driver rates Rider.
coupons_promos riders M : N rider_coupons (Junction) Promotional codes (e.g. RAPIDO50, UBERNEW) claimed and redeemed by riders.
rides support_tickets 1 : N support_tickets.ride_id Rider or Driver logs customer support issues (lost item, fare dispute).
Uber/Rapido Ride Booking & Execution Pipeline
Shows step-by-step data movement from Rider Search ➔ Driver Dispatch ➔ Live Tracking ➔ Fare Payment ➔ Rating Feedback. 
graph TD
    subgraph 1. Onboarding & Driver Verification
        D[Drivers] -->|Uploads Docs| DD[Driver Documents]
        DD -->|Admin Verified| DV[Verified Driver & Vehicle]
        VT[Vehicle Types] -->|Categorizes| DV
    end

    subgraph 2. Ride Request & Dispatch Engine
        R[Riders] -->|Selects Pickup/Drop & Vehicle Type| RR[Request Ride]
        SZ[Surge Zones Engine] -->|Calculates Dynamic Fare| RR
        RR -->|Broadcasts to Nearby Online Drivers| D
        D -->|Accepts Request| RA[Accepted Ride & OTP Generated]
    end

    subgraph 3. Trip Execution & Realtime Tracking
        RA -->|Driver Reaches Pickup| AP[Arrived at Pickup]
        AP -->|Rider Verifies OTP| TS[Trip Started]
        TS -->|High-Frequency GPS Pings| RL[Ride Locations Tracking]
    end

    subgraph 4. Completion, Payment & Review
        TS -->|Reaches Destination| TC[Trip Completed]
        TC -->|Generates Invoice| P[Payment Transaction]
        R -->|Pay via UPI/Cash/Wallet| P
        TC -->|Two-Way Feedback| RRV[Ratings & Reviews]
        P -->|Driver Earnings Credit| DE[Driver Wallet Payout]
    end
